# Portfolio Data

This guide owns the portfolio data model, calculation scope, reconciliation, and update procedure.

## Workspace data

`src/data/portfolio-detail.ts` contains 91 purchase lots with fees, a shared table of SPY adjusted prices by applied trading date, 108 dated dividend, withholding-tax, and financing-interest cash events, three corporate actions, and 21 month-end position, price, and XIRR snapshots. Amounts and prices are in USD; dates use `YYYY-MM-DD`. Cash-event amounts are signed: dividends are positive, taxes and interest are negative. Purchase costs are `grossAmount + fees`. Simulated SPY units use `grossAmount / adjustedClose`, while the full purchase cost is the simulated cash outflow; they are hypothetical holdings.

`src/data/portfolio.ts` derives the website's current holdings, cost basis, income, market value, and return history from those records. It also exports monthly simulated SPY units, values, and since-inception XIRRs through `portfolioSpyMonthlyReturns`, plus the latest comparison through `portfolioSpySnapshot`. Home, Portfolio, and Performance import this shared module. The application reads workspace data directly and does not need a database or a separate data-processing service.

The latest month-end valuation sets `asOf` for the published snapshot. Later purchases and cash events do not enter its cost basis, income or return; simulated SPY units include a purchase only after both its transaction date and applied price date. Detailed future records may be prepared before the next valuation without changing the currently published snapshot.

The published 2026-08-31 snapshot contains 18 holdings and 21 month-end observations. Stocks total USD 121,301.99; the simulated SPY value is USD 121,637.62. Idle cash, deposits, withdrawals, and currency exchanges are outside this stock-investment return model. The Performance chart shows since-inception annualized XIRR at each month-end, not each month's standalone return; horizons below 30 days remain unavailable.

## Calculation and updates

Keep source precision until display formatting. Portfolio cumulative return includes net dividends and deducts financing interest; individual holding returns compare market value with cost basis and do not allocate portfolio-level interest. The dated events support other cash-flow calculations, while the month-end prices and quantities support position-level valuation. Simulated SPY units and terminal values are derived from the recorded inputs; the XIRR observations are stored results, not recomputed by the website at request time.

Each month records the applied U.S. trading date, which precedes the calendar month-end when markets are closed. SPY is the only benchmark. Preserve previously published monthly prices and XIRRs unless the source evidence supports an explicit correction.

## Update and acceptance procedure

1. Identify the input revision before editing. In the change or release record, note the snapshot month, the source provider or dataset name and its available version or retrieval date, the price-adjustment basis, and the evidence review date. Use a non-private batch label if the transaction source has no public version. The Git commit identifies the published workspace-data revision. Keep statements, account identifiers, raw source files and local paths out of the repository and release record.
2. Add or correct dated purchases, cash events, corporate actions, applied SPY adjusted closes and month-end valuations in `src/data/portfolio-detail.ts`. Use the actual transaction date for purchases and the applied U.S. trading date for SPY prices; record both when they differ. Keep source precision until display formatting. Change `src/data/portfolio.ts` only if derivation or presentation rules change.
3. Reconcile against the reviewed inputs: purchase `shares × unitPrice = grossAmount`; purchase cost includes fees; signed cash events sum to net dividends and financing interest; corporate actions and purchases reproduce every month-end share count; `shares × price` reproduces stock value; each SPY purchase price matches its applied date; simulated units and terminal value reproduce the benchmark; stored portfolio and SPY XIRRs match the reviewed cash flows. The test independently recomputes SPY XIRR but does not recompute portfolio XIRR; retain independent calculation evidence for the latter in the private review record. Investigate every mismatch before changing expected test values.
4. Run `node --import ./scripts/register-server.mjs --test tests/portfolio-snapshot.test.mjs`. Its current tolerances are USD 0.0001 for purchase arithmetic, USD 0.001 for published cost and income totals, USD 0.011 for month-end valuations and SPY values, USD 0.01 for the latest SPY snapshot, 0.000001 SPY units and 0.0001 percentage point for SPY XIRR. Dates, counts and stored XIRR pairings are exact. These tolerances accommodate floating-point arithmetic; they do not permit a conflicting source price, missing event or unexplained account difference.
5. If displayed values or chart behavior change, run `npx playwright test tests/performance-chart.spec.ts tests/portfolio-form-status.spec.ts --project=chromium` and inspect the three language routes. Before deployment, run the full gate in [AGENTS.md](../AGENTS.md#verification-and-review). Accept the update only when the reconciliation, focused checks and affected pages agree with the identified source revision; record any corrected historical observation and its reason in the change review.

The application and CI use Node.js, TypeScript, and the existing test tools. Reading, updating, and calculating from the workspace data do not require Python or SQL. A one-time external data conversion may use Python when its spreadsheet or statistical libraries materially simplify that conversion; it is not a runtime dependency or a second source of portfolio data.
