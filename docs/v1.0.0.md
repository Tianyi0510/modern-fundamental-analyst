# Modern Fundamental Analyst 1.0.0

This is a release-planning document for the current checkout, not a record of a published release. Local review and test results do not establish remote CI, deployment, cloud telemetry or search indexing.

## Features

The planned first stable release includes:

### Web Content

- English, Traditional Chinese and Simplified Chinese pages with localized navigation, metadata and sharing previews.
- Portfolio holdings, allocation and sorting, with performance compared against SPY. Cumulative reconstructed TWR and since-inception annualized XIRR charts include monthly tables. Portfolio data reflects the 30 September 2026 snapshot.
- Investment memos with five localized categories, shareable filters and two clearly marked planned articles. Mobile shows one card and an expandable index. Articles include a table of contents and link copying.

### Web Application Architecture

- Next.js App Router, React and TypeScript, running on Node.js 24 LTS, with feature boundaries and server-side service modules.
- Unit and integration tests with Vitest, Testing Library and MSW, plus production-browser tests with Playwright in Chromium and WebKit.
- GitHub Actions verification with scoped credentials and identical-tree evidence reuse, calibrated performance budgets, native Lighthouse Baseline diagnostics and an exact-commit Vercel deployment gate.
- Article-specific typography styles loaded on investment memo article routes.

### Design System

- Responsive editorial layouts with Jost and Noto Sans typography, a Perfect Fourth type scale and shared design tokens. Simplified Chinese uses local font shards while retaining complete original glyph coverage.
- shadcn/ui components, Base UI interaction primitives and Lucide icons.
- Light and dark themes, reduced-motion support and localized accessible controls.

### Integrations

- Contact forms and email subscriptions through Resend, with localized confirmation emails, explicit double opt-in and encrypted preference links.
- Upstash Redis-backed subscriber coordination, recipient limits, replay protection and persistent delivery suppression. Confirmed consent is retained when welcome delivery requires reconciliation.
- One-time research support through Stripe Checkout with server-side payment verification.
- Sentry error tracking, tracing, logs, metrics and Session Replay, with asynchronous browser initialization, bounded early-error buffering, isolated capture failures and shared privacy filters.

## Known Limitations

- Scheduled uptime monitoring remains unverified after Sentry rejected activation; SDK telemetry is separate from uptime coverage.
- Portfolio returns use closing-price reconstructions rather than observed intraday valuations.
- Failed welcome deliveries require reconciliation; an automatic replay worker is not included.
- TypeScript 7 and ESLint 10 upgrades remain constrained by required lint-plugin compatibility. A development-only dependency advisory remains tracked in the [architecture guide](WEB_APPLICATION_ARCHITECTURE.md#dependency-versions).
- Physical iPhone acceptance remains unverified; automated WebKit tests do not establish physical-device compatibility.

Release acceptance follows the [architecture release workflow](WEB_APPLICATION_ARCHITECTURE.md#release-workflow). Native Baseline is diagnostic; local Lighthouse budgets, browser tests and SEO metadata checks do not establish field performance, historical-browser compatibility or search ranking gains.
